# Progression Policy

## Principio central

La progresión se decide por evidencia de dominio, no por calendario, entusiasmo ni resultados financieros recientes.

## Umbrales

- Mini examen de tema: **>= 80%**.
- Checkpoint semanal: **>= 85%**.
- Riesgo, apalancamiento, órdenes y position sizing: requisitos críticos.

## Estados

### NOT STARTED
No existe evidencia suficiente.

### IN PROGRESS
El tema ya fue introducido.

### EVIDENCE PENDING
La práctica existe, pero falta evaluación suficiente o aplicación independiente.

### MASTERED
Cumple criterio de dominio.

### REINFORCEMENT
Existe un error recurrente o crítico.

## Reglas de avance

Se permite avanzar cuando:

- el tema actual alcanza el umbral;
- no hay error crítico que contamine el siguiente tema;
- el alumno puede explicar el concepto en sus propias palabras;
- existe al menos una práctica correcta.

Si el alumno obtiene >=85% pero conserva una debilidad menor, se puede avanzar y programar recuperación espaciada.

## Bloqueos obligatorios

No se avanza a ejecución real si falta cualquiera de estos elementos:

- estrategia versionada y explicable;
- muestra histórica significativa;
- expectancy positiva en una muestra de evaluación;
- drawdown conocido;
- forward test/demo;
- cumplimiento consistente de reglas.

## Dinero real

Estado inicial: **LOCKED**.

El desbloqueo no depende de una racha ganadora.

## Cambio de estrategia

Toda modificación relevante requiere:

- versión anterior;
- problema observado;
- hipótesis;
- regla modificada;
- fecha de corte;
- nueva muestra.

No se mezclan resultados de versiones distintas como una sola estrategia.
